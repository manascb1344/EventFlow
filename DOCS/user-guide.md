## 2. Organizer flow

### 2.1 Sign up

Open **Create an event** or go to `/auth/organizer/signup`. Enter your full name, email, password, and password confirmation.

![Organizer sign-up](screenshots/03-organizer-signup.png)

### 2.2 Onboarding

New organizers are sent to `/onboarding/organizer` to add an organization name, phone number, and bio. Middleware blocks the organizer dashboard until onboarding is complete.

![Organizer onboarding](screenshots/04-organizer-onboarding.png)

### 2.3 Dashboard

The dashboard shows events published, tickets sold, revenue, and upcoming events.

![Empty organizer dashboard](screenshots/05-organizer-dashboard-empty.png)

### 2.4 Create an event

Go to **Create Event**. Fill in the name, location, start and end dates, venue, venue capacity, ticket price in rupees, seats on sale, registration deadline, and description. New events are published immediately.

![Create event form](screenshots/06-create-event.png)

The event then appears under **My Events**, and its detail page shows the schedule, venue, and sales tabs.

![Organizer events list](screenshots/07-organizer-events.png)

![Organizer event detail](screenshots/08-organizer-event-detail.png)

### 2.5 Analytics and settings

**Analytics** shows totals, revenue over time, and tickets by event. **Settings** holds the organizer profile and organization details.

![Organizer analytics](screenshots/09-organizer-analytics.png)

![Organizer settings](screenshots/10-organizer-settings.png)

## 3. Attendee flow

### 3.1 Sign up

Go to **Get Started** (`/auth/attendee/signup`) and enter an email and password. Google sign-in is also available.

![Attendee sign-up](screenshots/11-attendee-signup.png)

### 3.2 Onboarding

New attendees complete `/onboarding/attendee`: phone number (required), interests, dietary requirements, preferred payment method, and event update emails.

![Attendee onboarding](screenshots/12-attendee-onboarding.png)

After onboarding, the attendee dashboard opens with no tickets yet.

![Attendee dashboard before purchase](screenshots/13-attendee-dashboard.png)

### 3.3 Browse and save

**Browse Events** lists published events with search, date, and location filters. The bookmark icon saves an event; saved events appear under **Saved Events**.

![Event saved from the list](screenshots/14-event-saved.png)

![Saved events](screenshots/15-saved-events.png)

### 3.4 Buy a ticket (demo checkout)

Open the event and click **Register Now**. The price shown comes from the database.

![Event detail with Register Now](screenshots/16-event-detail.png)

The deployment runs with `DEMO_CHECKOUT=true`, so the ticket is issued without contacting Stripe and no payment is taken. The app redirects to the success page:

![Demo registration confirmed](screenshots/17-demo-checkout-success.png)

With `DEMO_CHECKOUT` off, the same button opens Stripe Checkout in test mode. Use card `4242 4242 4242 4242`, any future expiry, and any CVC.

### 3.5 After purchase

The ticket shows as **Confirmed** in **My Tickets**. One seat is reserved in the same database transaction, so the public event page drops from 120 to 119 available seats.

![My Tickets](screenshots/18-my-tickets.png)

![Seat count after purchase](screenshots/19-seat-count-after-purchase.png)

![Attendee dashboard after purchase](screenshots/20-attendee-dashboard-after.png)

Attendees can edit their profile details and notification preferences.

![Attendee profile](screenshots/21-attendee-profile.png)

![Attendee settings](screenshots/22-attendee-settings.png)

## 5. Issues found during this walkthrough

These were seen on the deployed app and are fixed in the code alongside this guide. The screenshots show the deployed behaviour before the fixes.

| Issue | Where | Fix |
| --- | --- | --- |
| After attendee sign-up, `/dashboard` and `/onboarding/attendee` redirected a signed-in user to the sign-in page | `app/dashboard/page.tsx`, `app/onboarding/*/page.tsx` | Wait for the session to finish loading before redirecting |
| Opening the event edit URL directly redirected to the home page | `app/dashboard/organizer/events/[id]/edit/page.tsx` | Same session-loading guard |
| Create Event saved the event but stayed on the form | `app/dashboard/organizer/events/create/page.tsx` | Navigate with `router.push` after a successful save |
| Organizer dashboard showed revenue as `$499.00` | `OrganizerDashboardContent.tsx` | Format with `formatCurrency` (₹) |
| Organizer dashboard always said "No upcoming events" | `OrganizerDashboardContent.tsx`, `app/dashboard/organizer/page.tsx` | Load and list the organizer's upcoming events |
| "Running / Currently live" card actually counted events created in the last month | `OrganizerDashboardContent.tsx` | Relabel to "New events / Created in the last 30 days" |
| Analytics showed `Infinity%` ticket growth | `_actions/analytics.ts` | Cast Postgres counts to numbers before comparing |
| Organizer event capacity showed `1/119 seats filled` | `EventDetailClient.tsx` | Use tickets sold plus seats remaining as the total |
| My Tickets showed a screenshot of a different event when an event had no banner | `public/images/placeholder-event.png` | Replace with a neutral placeholder |
| Edit form and PDF report used `$` | edit page, `lib/pdf-generator.ts` | Use rupees |

## 6. Known limitations

- Real Stripe payments still need Stripe account activation. The deployed app uses the labeled demo checkout.
- Organizers cannot upload an event banner from the UI. Banners only come from seed data.
- Attendee sign-up does not ask for a name, so the dashboard greets the attendee by the email prefix until they edit their profile.
- Receipt emails were not checked against a live inbox in this walkthrough.
